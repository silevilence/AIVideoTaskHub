# ComfyUI WebAPI Provider 需求规格

状态：已确认
确认日期：2026-08-22

## 目标

将 ComfyUI Web API 作为新的视频生成 Provider 接入。用户在设置中维护可复用的工作流模板；已启用模板作为该 Provider 的可选“模型”，创建任务时由模板变量生成动态表单，提交后沿用现有异步任务生命周期下载一个明确指定的视频结果。

领域术语以根目录 [`CONTEXT.md`](../../CONTEXT.md) 为准。

## 1. 范围与角色

- 模板作者在设置中维护 API 格式工作流、模板变量、主描述变量和主输出。
- 任务创建者选择工作流模板、填写变量并可临时覆盖 ComfyUI 地址。
- 系统负责离线校验、目标实例兼容性预检、图片上传、工作流渲染、排队、状态同步和结果下载。
- `comfyui` Provider 的模型列表等于当前已启用的工作流模板列表；模板使用稳定 ID，名称仅用于展示。

## 2. 工作流模板文档

### 2.1 存储与生命周期

- 每个模板以 SQLite 记录保存稳定 ID、启停状态、创建时间和更新时间。
- 模板的可移植正文必须保存为一个组合文档：开头是 YAML front matter，后面是纯 ComfyUI API 格式 JSON。
- YAML 元数据至少包含 schema 版本、模板名称、可选说明、变量定义、可选主描述变量和主输出选择器。
- 管理器打开模板时，将 YAML 元数据解析到独立管理面板；JSON 编辑区只显示 JSON 正文。
- 模板名称必填，并在有效模板中不区分大小写唯一。
- 编辑模板只影响之后创建的任务。停用或删除模板后，它不再出现在模型列表中；历史任务仍由任务快照支持查看、重试和套用。

示例文档：

```yaml
---
schemaVersion: 1
name: 基础文生视频
description: 使用默认采样器生成视频
primaryDescription: prompt
primaryOutput:
  nodeId: "12"
  field: videos
  index: 0
variables:
  - key: prompt
    label: 提示词
    description: 视频画面描述
    type: string
    multiline: true
    minLength: 1
  - key: steps
    label: 采样步数
    type: integer
    default: 20
    min: 1
    max: 100
    step: 1
---
{
  "6": {
    "class_type": "CLIPTextEncode",
    "inputs": {
      "text": "${prompt}"
    }
  },
  "10": {
    "class_type": "KSampler",
    "inputs": {
      "steps": "${steps}"
    }
  }
}
```

### 2.2 支持的 JSON 格式

- 首版只接受 ComfyUI “Save (API Format)” 产生的 API 格式工作流，即以节点 ID 为键、节点包含 `class_type` 和 `inputs` 的 JSON 对象。
- UI/画布 Workflow JSON 不自动转换；管理器应识别常见 UI 格式并给出如何导出 API 格式的明确提示。
- JSON 编辑器必须提供 JSON 语法高亮、格式化和包含行列位置的语法错误提示。

### 2.3 模板变量

- 变量键必须匹配 `[A-Za-z_][A-Za-z0-9_]*`，区分大小写并在模板内唯一；显示名与说明可使用任意文本。
- 首版支持 `integer`、`number`、`string`、`boolean`、`option`、`image`。
- 所有在 JSON 中使用的变量都是任务必填项；默认值只用于创建页预填，不改变必填语义。
- 整数和小数可定义 `min`、`max`、`step`；默认值必须为有限数且满足约束。
- 字符串可定义单行/多行、`minLength`、`maxLength`；默认值必须满足约束。
- 选项至少包含一个项目；每项包含显示名和唯一内部字符串值，默认值必须属于选项集合。
- 布尔默认值必须是布尔值。图片默认值如存在，必须是创建页可识别的图片来源。
- 变量只能出现在节点 `inputs` 下的 JSON 字符串值中，不能用于节点 ID、对象键或 `class_type`。
- 变量引用统一写成合法 JSON 字符串令牌，如 `"${steps}"`。
- 当整个字符串恰好是一个令牌时，按变量声明类型替换为真正的 JSON 值；只有 `string` 变量允许在更长字符串中内嵌插值。
- 同一变量可被引用多次，所有引用必须得到同一值。

### 2.4 主描述与主输出

- 模板可指定一个 `string` 变量为主描述变量；其任务值写入现有任务描述，用于列表摘要、搜索和 MCP 返回。
- 不提供内置 `${prompt}`。未指定主描述变量时，以模板名称作为任务描述。
- 每个模板必须定义一个主输出选择器：节点 ID、输出字段名和非负文件序号（默认 0）。
- 主输出节点必须存在于工作流。运行完成后，选择器必须解析到可下载的标准 ComfyUI 文件描述；否则任务失败并记录具体原因。
- 首版每个任务只保存和展示一个主输出，不保存其他工作流产物。

## 3. 模板管理

- 设置中新增“ComfyUI 工作流”管理入口。
- 支持列表搜索、新建、编辑、复制、启用/停用、删除、导入和导出单个模板。
- 导入和导出使用第 2 节定义的组合文档，不另设私有格式。
- 复制模板必须生成新稳定 ID，并要求使用新的唯一名称。
- 删除需要确认，但不因历史任务引用而阻止；历史任务使用自己的快照。
- 变量管理、主描述和主输出在 JSON 编辑器之外显示为结构化面板。

## 4. 模板保存校验

### 4.1 阻止保存的错误

- YAML 元数据无法解析或 schema 版本不受支持。
- JSON 非法、根不是对象、不是 API 格式，或节点缺少合法 `class_type`/`inputs`。
- 模板名称缺失或重复，变量键重复或非法。
- 变量类型配置、约束、选项或默认值非法。
- JSON 使用了未定义变量，变量出现在 `inputs` 值之外，或非字符串变量用于内嵌插值。
- 主描述变量不存在或不是字符串类型。
- 主输出节点不存在，字段为空或序号非法。

### 4.2 可确认后保存的警告

- 变量已定义但未在 JSON 中使用。
- 用户必须明确确认警告后才能继续保存；再次保存的确认只针对当前校验结果。

### 4.3 在线兼容性检查

- 模板管理器提供可选的“检查默认 ComfyUI”操作，通过默认地址读取 `/object_info`。
- 检查结果应列出缺失节点类型和可识别的输入不兼容；地址不可达也要显示清晰原因。
- 在线检查失败不阻止模板离线保存，因为任务可以使用不同地址。

## 5. ComfyUI 连接设置

- Provider 设置中可保存一个默认 ComfyUI Base URL，并提供连通性测试。
- Base URL 仅允许 `http` 或 `https`，保存和使用时规范化尾部斜杠。
- 创建任务时地址输入框由默认值预填，允许为本次任务临时修改；临时值不得回写默认设置。
- 首版只支持无认证连接，不支持 API Key、认证代理或自定义请求头。

## 6. 创建任务

- 选择 `comfyui` 后，只列出已启用模板；没有可用模板时给出进入工作流管理的引导。
- 选择模板后，按 YAML 中的变量顺序渲染表单，并展示变量显示名、说明和约束。
- 有默认值的字段自动填入默认值；无默认值的字段保持空白。
- 图片变量复用现有本地上传、已上传图片库和 URL 输入能力。
- 前端在提交前校验全部变量非空且满足类型约束；后端必须重复同样的权威校验，不能信任前端结果。
- 后端使用本次实际 Base URL 强制读取 `/object_info`，确认工作流所需节点存在，并检查可识别的节点输入兼容性。
- 地址不可达、兼容性检查失败、缺少节点或输入不兼容时，阻止创建本地任务和远端排队，并一次性返回可定位的问题清单。
- 强制预检不得复用其他地址的结果；如使用缓存，缓存键必须包含规范化后的实际地址，且提交时仍需满足新鲜度要求。
- 预检通过后，图片由后端获取并上传到目标 ComfyUI `/upload/image`，再将 ComfyUI 返回的文件标识作为图片变量值。
- 渲染后的工作流仍必须是合法 API 格式 JSON；变量值不得通过文本拼接破坏 JSON 或注入结构。
- 本地任务创建时保存任务快照，至少包含模板稳定 ID 与名称、完整组合文档、变量原值、图片解析结果、主输出规则和实际 Base URL。

## 7. 提交、轮询与结果下载

- 通过目标实例 `POST /prompt` 提交渲染后的 API 格式工作流，并保存返回的 `prompt_id`。
- `/prompt` 返回的工作流校验错误和 `node_errors` 必须转换为可读的失败信息。
- 沿用现有 `pending → running → success / failed` 生命周期，不新增百分比或当前节点字段。
- 后台轮询通过目标实例的队列与 `/history/{prompt_id}` 判断排队、执行、成功和失败；轮询始终使用任务快照中的地址。
- 成功后按任务快照中的主输出选择器定位文件，通过 ComfyUI 文件查看接口下载到现有本地视频目录，并写入 `result_url`。
- 执行错误、历史记录中的失败、主输出缺失、文件描述非法或下载失败，都必须将任务置为 `failed` 并保留可诊断错误。

## 8. 历史任务与现有能力兼容

- 模板编辑、停用或删除不改变既有任务的显示、轮询、下载或重试。
- 重试使用任务快照中的工作流、变量、主输出和地址，并再次执行实际地址兼容性预检。
- “套用参数”打开可编辑的历史快照表单；即使原模板已停用或删除，也允许修改变量和临时地址后创建新任务，并明确标注来源为历史快照。
- 任务详情和回收站详情应展示模板名称、变量值、主输出规则和实际地址；图片变量继续支持预览。
- 删除与彻底删除沿用现有任务和媒体清理规则；模板删除不删除任务媒体。
- MCP `get_models` 将已启用模板列为 ComfyUI 模型；`get_param_spec` 返回变量 schema；`submit_task` 接受模板变量和可选临时地址，并执行与 Web 创建页相同的后端校验和预检。

## 9. 验收与测试要求

- 所有新增业务逻辑按仓库 TDD 规范先补测试，数据库测试使用内存 SQLite，API 测试使用 Supertest。
- 单元测试覆盖组合文档解析/序列化、API 格式识别、变量引用扫描、类型替换、默认值与约束、错误/警告分级、主输出解析。
- Provider 测试覆盖连通性、强制 `/object_info` 预检、图片上传、`/prompt` 提交、队列/历史状态映射、错误映射和结果下载。
- API/UI 逻辑测试覆盖模板 CRUD/启停/导入导出、动态表单默认值、前后端提交校验、默认与临时地址、任务快照、重试和套用参数。
- 回归测试确认其他 Provider 的创建、轮询、重试、任务详情、回收站和 MCP 行为不变。

## 10. 首版不包含

- UI/画布 Workflow JSON 到 API 格式的转换。
- ComfyUI 认证、API Key 或自定义请求头。
- 多资产保存、图片/音频附属结果或输出画廊。
- WebSocket 百分比、预览图或当前节点进度。
- 可选变量、条件显示、变量依赖、数组或任意 JSON 类型变量。
- 工作流目录、标签、手工排序、批量导入或模板版本历史。
